# Managed local Temporal delivery

Status: implementation plan for an experimental, single-host runtime. The local service delivers an authorized development issue to a verified **open, unmerged pull request**. It does not merge, release, deploy, mutate personal production data, or change the existing Devflow installation. The earlier [role-ordering MVP](2026-09-25-temporal-runtime-mvp.md) remains a disposable demonstration.

## Contract and design

1. Accept a command ID, run/work/issue IDs, goal, accepted plan, configured repository key and base, branch, and `published_unmerged` authorization. An allowlisted private service policy owns filesystem paths, role models/efforts, check commands, required CI names, Project target, and recovery imports. An identical retry returns the same run; conflicting IDs or inputs fail before effects. An atomic local claim and outbox intent precede Temporal start, with a remote memo readback after interrupted dispatch.
2. Prepare a new owned Git worktree at the accepted base. Import only explicitly selected files from an abandoned source, with a source manifest and patch provenance; never modify that source. Bind the candidate to base/head, Git-visible content and executable modes, environment, and frozen policy. Safe internal tracked symlinks are hashed by path and link target; escaping links fail.
3. Run the implementation role through agent-runtime-kit in an owned native Codex permission profile, then publish the first meaningful candidate as a regular PR. Run independent review and verification on the candidate; actionable findings return to the original implementation session for at most the configured repairs. Every candidate change invalidates affected gates. Local checks and required CI must pass before the broker reconciles the issue and releases its external claim. The broker owns Git and GitHub authority; roles cannot choose remotes, merge, or release.
4. Treat model and candidate-controlled shell commands as untrusted. Model command tools use a named native permission profile with provider authentication held in the trusted CLI. Candidate-controlled install/build/test commands use a separate credential-free check profile. Reject tracked project Codex configuration, unsafe Git filters and hooks, unapproved network domains, executable drift, and stale sandbox attestation. Negative probes must cover direct and child outside writes, broker state and credentials, and network, alongside owned writes and actual local toolchain checks. Unsupported host control blocks real admission.
5. Supervisor capacity and process identity govern role launch. Completed receipts replay only for the same run/input/candidate. Interrupted or ambiguous effects become explicit unknowns, never automatic duplicate work. Cancellation takes precedence over a concurrent result. A durable decision uses ID, run revision, and candidate revision and survives worker restart without a model call while waiting.
6. Expose one service through CLI, authenticated loopback HTTP, official MCP stdio, and a static dashboard. The dashboard renders only persisted gates, queue/roles, PR/candidate, checks, tracker, usage provenance, decisions, and an SSE-replayed timeline. Disconnection shows stale observations; display refresh is deterministic. Local start/status/stop own Temporal dev server, worker, and API processes.

## Required evidence

Run locked Python tests and lint, dashboard build/tests, real Temporal restart/repair/cancel integration, actual native model/owned-write and authority-denial probes, credential-free check probes with permitted package install and QA, MCP protocol/auth/path negatives, and a browser run against the real service including SSE disconnect/reconnect. Review and verification must inspect the exact pushed Devflow PR candidate. A selected real repository trial must be submitted through the public runtime and have implementation, early PR, independent gates, repairs, CI, and issue reconciliation performed by the runtime and kit. Record requested model/effort separately from provider-observed model; leave unavailable fields unknown. Final artifacts are open verified PRs and a useful running local dashboard. No successful fake run substitutes for this trial.
