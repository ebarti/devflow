# Architecture

The host discovers eight sibling skills. The main Astra task performs inspection, user clarification and planning, then hands authorized implementation to a Sol/high execution coordinator. Four [agent definitions](../skills/devflow/references/agents.md) configure that coordinator and its three leaf roles: implementation, review and verification use Sol/xhigh. The coordinator owns routine dispatch, repair loops, records, issue updates, authorized comments and merges. Leaves never delegate. Material design decisions return to the main task. Standalone review/verification can use a leaf directly, and a merge-only request runs in the main task.

The implementer opens PRs early and pushes repairs. Sequential unmerged work forms one gh stack; [PR workflow](../skills/devflow/references/pr-workflow.md) owns the branch/publication rules. There are no definer, planner or delivery agents. The [implementation worker](../skills/devflow/references/implementation-worker.md) reference defines implementation scope, reuse and failure handling. The main [devflow skill](../skills/devflow/SKILL.md) owns routing. Skill references are canonical for agent-facing behavior; these docs describe components and storage.

`skills/devflow/scripts/state.py` uses Python's standard library to store local records, reserve work for an owning task, bind that task's runtime session and query metrics. Issue claims are atomic within a shared SQLite database. Independent work executes outside those short transactions.

`skills/devflow/scripts/github.py` uses the authenticated `gh` CLI to create or reuse issues, assign the responsible user and update the existing Project's Status. Its read-only audit compares persisted expectations with live issue, Project and tracked Actions state; creation, readback and ownership guarantees are in the [storage contract](implementation-contracts.md). Neither helper starts agents or runs project checks.

The main task holds the claim. The execution coordinator acts for that owner with the same database and inherited permissions; leaf workers report evidence and never write the shared records. `telemetry.py` installs lifecycle hooks, inherits a single work ID through both delegation levels, and denies recognized repository write commands from either the main claim holder or execution coordinator. `measurements.py` derives timings, outcomes, recovery and coverage from the same database. Collection scope and limits are defined in [work records and metrics](../skills/devflow/references/state.md#usage).

The installer links skills from a release checkout, copies regular agent definitions into Codex home and merges the collector into the host's hook configuration. An ownership manifest lets explicit upgrades refresh unchanged agent copies and remove obsolete unchanged copies; custom or modified copies are preserved. A small copied hook guard checks the checkout content, skill links and matching agent copies against the installation snapshot before loading mutable source; drift surfaces an actionable message. Other agents and hooks are preserved; the host owns hook trust. Candidate sessions use separate configuration, skills, agent definitions and SQLite, with Astra/xhigh as their main-task default. Normal installation leaves host model settings unchanged. Delegated model defaults are pinned in the installed agent definitions, never chosen at spawn time.

Agent prompts specify methods and report formats; input/output validation and enforced sequencing are deferred. Hook rules are a backstop rather than a complete enforcement boundary.

Helper behavior is covered by `tests/` (claims, replay, migration, transcript collection, issue creation) and by the installation smoke check in `scripts/check-install.sh`.
