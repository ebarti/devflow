# Implementation

Read the accepted contract and `next` result. Confirm branch, worktree ownership, and dirty state. Preserve unrelated files. A registered task checkout is the implementation boundary; leave canonical checkouts alone.

Implement the smallest coherent change satisfying acceptance. Diagnose observed defects from source to result before changing presentation. Maintain owning docs when behavior or a contract changes. Add regression proof for the invariant; do not add tests merely to mirror code.

Capture a clean candidate before verification. Execute the admitted repository recipes through `check run`; store additional product observations as evidence. Changed policy cannot reduce its own admitted checks. Changed code creates a new candidate and invalidates affected gates; reuse only evidence whose inputs still match.

Record confirmed findings immediately, including those discovered before formal review. Repair them in the owner task. Request targeted reruns from the same independent role. Failed attempts and repairs remain in history and accounting.

Run only applicable checks. An editorial change needs static proof, scoped changes require review, product changes require review and QA, and high-risk changes require their relevant full matrix. Approved unreleased stacks follow their explicitly adopted cumulative gate policy.
