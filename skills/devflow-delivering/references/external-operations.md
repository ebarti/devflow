# External operations

Use structured JSON request files and stable operation IDs. Read the current schema and `next`; the CLI computes hashes/revisions. Do not interpolate issue/comment text into shell commands.

Branch updates use `push_branch`. Expected remote head distinguishes creating a missing branch from updating one. Dispatch verifies the owned clean candidate and uses a guarded Git update. Lost responses require remote-ref reconciliation before another mutation.

Publish/update PRs/findings through recorded actions. Anchor failures retain sanitized API validation evidence. Compatibility fallback is permissible only after definite no-mutation rejection and validated mapping against the exact diff. Network uncertainty never authorizes a second visible comment.

Endpoint operations originate from `deliver` after proof validation. Automatic protected merge requires enrolled protection/conformance, expected heads and integrated-tree readback. Native user-authorized stack merge retains its actual tool/receipt evidence and is not an automatic-protection claim.

After failure, inspect dispatch, receipts and remote state. For proven rejection, correct the prerequisite and retry the same action. For uncertain success, reconcile the actual endpoint; absence in one eventually consistent read is insufficient to duplicate a write.
